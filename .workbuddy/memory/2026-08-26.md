## 战略分析：开放技术顶点 vs 闭源壁垒（readme.frontier.md）

- 用户追问：下载技术是否到开放顶点？能否攻克闭源顶级技术？产出 `readme.frontier.md`。
- 结论：①**未到开放顶点**——BBRv3（2026-03 IETF 草案、合入 Linux 6.x、Win11 24H2 带 BBRv2）与 HTTP/3/QUIC（CDN 全量）均为成熟开放标准未采用；BBR 是最高杠杆零协议改动增益（弱网 +45%~+120%）。②**闭源分两类**：IDM 纯客户端加速无秘密封闭算法（XDM 已开源复刻，FluxDown 的 AIMD 更优），无需攻克；迅雷/百度加速的真正壁垒是**服务器舰队+带宽+P2P swarm+内容缓存（资本/基础设施）非算法**，单靠代码无法复刻，但可**自建开放等效**（自有 VPS/NAS 跑 aria2+yt-dlp 做离线下载 + FluxDown 客户端），零逆向零合规风险。③私有协议/DRM 逆向属法律灰区、脆弱、污染 AGPL 合规，**禁止**。
- 战略对齐：BBR 上调至 P1（高于 gap.md 原 P3），自建离线下载 companion 列为 P1 架构级新能力。

## 路线图：未实现技术 + 速度物理边界 + 功能探索（readme.roadmap.md）

- 用户追问：还有哪些下载技术未实现？探索速度硬件/网络底层边界？还能探索哪些功能设计？产出 `readme.roadmap.md`。
- 已核实基线纠正：代理能力（`auto_proxy.rs` 三路测速+故障转移）**已实现且先进**，非缺口；校验仅 BT 有 piece hash，HTTP 层 end-to-end checksum **未实现**；SFTP/WebDAV/FTPS/metalink 多镜像聚合 **未实现**（grep 无命中）。
- 未实现技术分类：协议补完（QUIC/SFTP/WebDAV/metalink/MPTCP/WebTransport/Tor/IPFS）、校验（HTTP checksum+坏块修复）、多源协同（同源镜像/跨协议聚合/自建P2P/LAN缓存）。
- 速度物理边界（核心命题）：软件只能逼近 ISP/NIC/磁盘/CPU 硬上限，不可超越；分段解除服务端单连接限速+单连接窗口限制，BBR 解除弱网缓冲膨胀。给出 BDP=CWND/RTT、1Gbps=125MB/s 磁盘不绑定、10Gbps 才触 SSD 等量化边界 + 边界总图 + 实测实验清单。
- 路线图优先级：P0 per-host 画像持久化；P1 HTTP checksum+坏块修复、metalink、BBR 启用、全局限速+瓶颈可视化、自建离线下载 companion、LAN P2P 缓存；P2 SFTP/WebDAV、Tor、跨协议续传；P3 QUIC、IPFS、MPTCP。
